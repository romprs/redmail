# RedMail — почтовый клиент для РЕД ОС

Настольный почтовый клиент для РЕД ОС 8 (Linux), функциональный аналог
Microsoft Outlook: почта по IMAP/SMTP и Microsoft Exchange (EWS), локальные
архивы писем с импортом из Outlook (.pst), mbox и Maildir, календарь с
приглашениями на встречи по iTIP, синхронизацией по CalDAV и EWS, адресная
книга, единый вход по Kerberos. Интерфейс — Qt 6 (PySide6), русский язык.

## Что умеет

**Почта.** Несколько учётных записей одновременно, каждая своей веткой в
дереве папок; выключатель у записи закрывает соединение, сохраняя настройки
и локальную копию, а обратная галочка подключает её сразу. Полная локальная
копия писем в SQLite: список и чтение работают без сети, обход сервера идёт
в фоне порциями. Папки, флаги, цветные маркеры, правила раскладки писем,
потоки по теме, поиск, вложения, подписи, пересылка и ответы.

**Категории писем (подключаемый модуль).** Уведомления и рассылки, обращения
и запросы, реклама и свои категории с описанием по адресатам и словам темы;
признаки рассылок в заголовках и дообучение на ручной разметке. Хранится
только локально. Сторонние модули подключаются через точку входа
`redmail.plugins`.

**Exchange (EWS).** Почта и календарь по одному подключению, вход по
Kerberos или паролю. Синхронизируются только почтовые папки: задачи,
заметки, контакты, журнал и служебные папки сервера пропускаются.
Ограничение частоты запросов на стороне сервера обрабатывается ожиданием, а
не ошибкой. Календарь Exchange заводится сам при подключении записи.

**Хранилище.** Профиль с тремя базами (почта, календарь, контакты) и
каталогом архивов. Автоархив по размеру базы: самые старые письма
переносятся в файлы `.rmarchive`, база ужимается; окно обслуживания
задаётся часами, удаление писем с сервера по умолчанию выключено.

**Календарь.** Недельный, месячный и списочный виды, несколько календарей с
разными источниками (локальный, CalDAV, подписка .ics, Exchange),
приглашения iTIP с ответами участников, масштаб шрифта настраивается.

**Адресная книга.** Импорт vCard и CSV, группы, должность и подразделение,
фотографии, представление карточками с аватарами, подстановка получателей
при наборе.

**Переход между почтовыми системами.** Правила замены домена при отправке
(письмо на старый адрес уходит на новый), две записи с одним адресом в
разных системах живут одновременно и различаются по протоколу и серверу.

**Перенос и выгрузка.** Профиль целиком (настройки, почта, календарь,
контакты, архивы) — одним файлом `.rmprofile` на другой компьютер; вся
переписка — в mbox или EML. Кто выгружает — сотрудник или только
администратор (`redmail --export-mail … --home …` от root), задаёт
оформление организации; каждое действие пишется в системный журнал.

**Фирменное оформление.** Функциональность под брендбук заказчика: у каждой
организации свой файл JSON — цвета, шрифт программы, шрифт и цвет письма,
колонтитул при отправке и шаблон стандартной подписи из карточки сотрудника.
Администратор раскладывает оформления в `/etc/redmail/brands`, пример —
`docs/brands/пример-организации.json`.

**Безопасность и окружение.** Пароли в системном хранилище ключей, доверие
корневым сертификатам организации из системного хранилища или из указанного
PEM-файла, работа в закрытом контуре без интернета.

## Установка на РЕД ОС

Готовый пакет самодостаточен (все зависимости внутри), интернет не нужен:

```bash
sudo dnf install ./redmail-0.0.1-<сборка>.red80.x86_64.rpm
redmail
```

Инструкция по установке, настройке учётных записей, Exchange, календаря,
сертификатов и обслуживанию базы — `docs/УСТАНОВКА_И_НАСТРОЙКА.md` (она же
собирается в .docx через `docs/build_manual.py`). Документы для регистрации —
`docs/registry/out/`.

## Сборка пакета

На машине с РЕД ОС 8 и доступом к PyPI (нужен только для сборки):

```bash
sudo dnf install rpm-build python3-devel python3-pip gcc make automake libtool autoconf \
    zlib-devel bzip2-devel openssl-devel krb5-devel git
packaging/build_rpm.sh
# результат: ~/rpmbuild/RPMS/x86_64/redmail-0.0.1-<сборка>.red80.x86_64.rpm
```

Версия сборки и перечень изменений — в `packaging/redmail.spec` (Release и changelog).

## Запуск из исходников (разработка)

```bash
python -m venv .venv
.venv/Scripts/pip install -e .          # Linux: .venv/bin/pip
.venv/Scripts/python -m redmail
```

## Локальный канал управления (IPC)

Запущенное окно слушает локальный сокет `redmail-ipc`
(`src/redmail/ipc_server.py`) — через него внешняя программа просит открыть
письмо или встречу с готовыми полями. Основной потребитель — голосовой
помощник `audioreferent`, он объявлен в пакете как рекомендуемый и ставится
рядом. Только локальный сокет, никакого TCP; доступ — тому же пользователю ОС.

Протокол построчный JSON: одна строка `{"action": ..., "args": {...}}` —
одна строка ответа `{"ok": true, ...}` либо `{"ok": false, "error": "..."}`.
Команды: `ping`, `focus`, `compose_email`, `create_event`, `update_event`,
`find_events`, `cancel_event`, `event_form_open`, `event_form_set`,
`event_form_state`, `event_form_save`, `event_form_cancel`, `find_contacts`,
`contact_picker_open`, `contact_picker_select`, `contact_picker_state`,
`contact_picker_accept`, `contact_picker_cancel`, `event_form_focus`,
`list_calendars`, `apply_mail_rules`,
`list_mail_rules`.

Пошаговая форма встречи (`event_form_*`) — для голосового заполнения «на
открытом окне»: `event_form_open` показывает обычное окно встречи (новой,
либо своей по `uid`) и держит его открытым, `event_form_set` меняет поля
прямо в нём по одному (`subject`, `date`, `time`, `start`,
`duration_minutes`, `recurrence` = none/daily/weekly/monthly/yearly,
`participants`/`add_participants`, `location`, `description`, `all_day`,
`calendar` — название, как его произносят: «эксчейндж», «вк», «мои встречи»,
номер из `list_calendars` или id) —
человек видит каждое изменение, `event_form_save`/`event_form_cancel`
нажимают «Сохранить»/«Отмена». `find_contacts` ищет в адресной книге по
фамилии/имени так, как их слышно в речи (с падежным окончанием: «Шилкина»
→ Шилкин), возвращая адреса для `participants`. Пара `contact_picker_*`
делает то же с открытой адресной книгой: показать список по запросу,
отметить нужных голосом по номеру, подтвердить или закрыть.

`update_event`/`cancel_event` требуют `uid` встречи — голосовая сторона его
не знает, у неё есть только тема (и, возможно, дата). `find_events` (`subject`
— подстрока темы, необязательно; `date` — `YYYY-MM-DD`, если не задана, берётся
сегодняшняя) возвращает список подходящих встреч с `uid`, по которому уже
можно вызвать `update_event`/`cancel_event`.

Всё, что отправляет что-либо наружу (письмо, приглашение, отмена встречи),
только ОТКРЫВАЕТ обычный диалог с заполненными полями — «Отправить»/
«Сохранить»/«Да» нажимает человек. Без подтверждения выполняются лишь
`focus`, `find_events`, `list_mail_rules` и `apply_mail_rules` (перекладывание
писем между папками того же ящика).

Проверить руками (или из голосового помощника audioreferent):

```bash
python3 scripts/ipc_client_test.py ping
python3 scripts/ipc_client_test.py compose_email --to ivan@example.com --subject Тест
python3 scripts/ipc_client_test.py create_event --subject Планёрка \
    --start 2026-09-10T15:00 --duration 30 --participants a@e.com,b@e.com
```

Фактический адрес сокета работающее приложение пишет в
`<каталог настроек>/ipc-endpoint.json`, скрипт читает его оттуда.

## Тесты

```bash
.venv/Scripts/pip install pytest
.venv/Scripts/python -m pytest -q
```

Тесты покрывают разбор IMAP, SMTP-кодирование, архивы, календарь и iTIP,
CalDAV (обнаружение календарей, синхронизация), Kerberos/GSSAPI и интерфейс
(в режиме без экрана, `QT_QPA_PLATFORM=offscreen`) — без реальных серверов.

## Состав

| Модуль | Назначение |
| --- | --- |
| `redmail/imap_client.py` | сеанс IMAP: папки, письма, флаги, маркеры, переподключение |
| `redmail/smtp_client.py` | отправка писем, вложения, встроенные изображения |
| `redmail/ews_client.py` | Microsoft Exchange (EWS): папки, письма, отправка |
| `redmail/ews_calendar.py` | встречи Exchange по тому же подключению |
| `redmail/gssapi_sasl.py` | единый вход Kerberos для IMAP/SMTP |
| `redmail/mailbox.py`, `cache_store.py` | локальная копия почты (SQLite) |
| `redmail/sync_engine.py` | обход папок: заголовки, флаги, докачка тел |
| `redmail/autoarchive.py` | перенос старых писем в архив по размеру базы |
| `redmail/archive_store.py` | архивы `.rmarchive`, импорт .pst/mbox/Maildir |
| `redmail/profile.py`, `config_store.py` | профиль пользователя и все настройки |
| `redmail/calendar_store.py`, `itip.py` | календарь, приглашения iTIP, .ics |
| `redmail/caldav_sync.py`, `ics_subscription.py` | CalDAV и подписки по ссылке |
| `redmail/contact_store.py` | адресная книга, импорт vCard/CSV, группы, фото |
| `redmail/address_rules.py` | замена домена получателя при отправке |
| `redmail/tls_trust.py` | доверие корневым сертификатам организации |
| `redmail/html_cleanup.py`, `remote_images.py` | подготовка HTML писем к показу и правке |
| `redmail/secret_store.py` | пароли в системном хранилище ключей |
| `redmail/applog.py` | журнал программы |
| `redmail/ipc_server.py`, `voice_assistant.py` | локальный канал управления |
| `redmail/plugins/` | подключаемые модули, в том числе категории писем |
| `redmail/ui/` | главное окно, недельный календарь, темы оформления |

Данные пользователя: `~/.config/redmail` — настройки и журналы, внутри
каталог `profile` с базами `mail.sqlite3`, `calendar.rmcal`,
`contacts.rmcontacts` и каталогом `archives` (файлы автоархива). Каталог
профиля можно перенести на другой диск в «Параметрах». Пароли — в системном
хранилище (Secret Service/keyring), в файлах настроек их нет.
