# Почтовый клиент RED OS: установка, настройка, диагностика

Документ описывает установку почтового клиента и голосового помощника на
RED OS 8, подключение учётных записей (IMAP/SMTP, Exchange, календарь),
работу с корпоративными сертификатами, настройки хранилища и разбор
типовых сбоев. Версия документа: сборка почты 0.0.1-104, помощник 0.1.0-8.

## 1. Что входит в поставку

| Пакет | Назначение | Размер |
|---|---|---|
| `redmail-0.0.1-<сборка>.red80.x86_64.rpm` | почтовый клиент: почта, календарь, контакты | ~210 МБ |
| `audioreferent-0.1.0-<сборка>.red80.x86_64.rpm` | голосовой помощник (распознавание Vosk, синтез Piper) | ~700 МБ |

Помощник — отдельный продукт и необязательная часть. Почта объявляет его
рекомендуемой зависимостью и работает без него.

## 2. Установка

Оба пакета ставятся одной командой, тогда помощник подтянется вместе с
почтой:

```bash
sudo dnf install ./redmail-0.0.1-104.red80.x86_64.rpm ./audioreferent-0.1.0-8.red80.x86_64.rpm
```

Только почта:

```bash
sudo dnf install ./redmail-0.0.1-104.red80.x86_64.rpm
```

Помощник не предлагается автоматически, если он не указан в той же команде
и недоступен в подключённом репозитории: dnf не просматривает каталог с
файлом пакета. После установки почта об этом напоминает.

Проверка установленного:

```bash
rpm -q redmail audioreferent
rpm -V redmail            # пусто — все файлы целы
```

Что видно в выводе dnf при обновлении: сначала ставятся файлы новой
версии, затем удаляются остатки старой и выполняются её сценарии. Поэтому
строка «Запуск скриптлета» относится к прежней версии — это её удаление,
а не установка. Номер работающей сборки всегда можно посмотреть так:

```bash
rpm -qf --queryformat '%{VERSION}-%{RELEASE}\n' /opt/redmail/venv/lib/python3.11/site-packages/redmail/__main__.py
```

Тот же номер программа показывает на заставке, в «Справка → О программе» и
пишет в журнал при запуске.

Удаление:

```bash
sudo dnf remove redmail audioreferent
```

Профиль пользователя (письма, календарь, контакты, архивы) при удалении
пакета не трогается, он лежит в домашнем каталоге.

## 3. Первый запуск и учётная запись

Запуск: «Почтовый клиент RED OS» в меню приложений или `redmail` в
терминале. Программа запускается в одном экземпляре: повторный запуск
поднимает уже открытое окно.

Параметры → вкладка «Учётные записи» → «Добавить учётную запись…».
Откроется окно учётной записи:

- **Входящая почта (IMAP)**: сервер, порт (обычно 993), способ входа,
  логин, пароль, SSL. Кнопка «Проверить подключение».
- **Исходящая почта (SMTP)**: сервер, порт (587 со STARTTLS или 465 с
  SSL напрямую), тот же логин и пароль.
- **Архив и переезд**: удаление писем с сервера после архивации и замена
  доменов получателей — только для этой записи.

Чтобы поменять уже подключённую запись, выделите её в списке и нажмите
«Настроить…» (или дважды щёлкните по ней). Если у записи сменились сервер
или логин, она переподключается. Выключенная галочкой запись только
сохраняется и подключится, когда её включат.

**Пароль приложения.** Некоторые серверы (в том числе VK WorkMail) не
принимают обычный пароль учётной записи в почтовых программах и отвечают
`NEOBHODIM parol prilozheniya / Application password is REQUIRED`. Нужно
создать пароль приложения в веб-интерфейсе почты и указать его вместо
обычного. Программа показывает эту подсказку прямо в окне ошибки.

**Вход по Kerberos (SSO).** Поддерживается, но зависит от сервера. Если
сервер объявляет GSSAPI в списке возможностей, а обмен обрывает
протокольной ошибкой, вход по Kerberos невозможен со стороны сервера, не
клиента. В журнале это выглядит так: «сервер заявляет поддержку GSSAPI, но
сам обмен аутентификацией прерывается протокольной ошибкой». Рабочий обход
— вход по логину и паролю приложения.

**Несколько учётных записей и переключение между ними.** Список
подключений — Параметры → вкладка «Учётные записи». Галочка слева это
выключатель:

- Снятая галочка отключает запись: соединение закрывается, ветка папок
  исчезает из дерева. Настройки и локальная копия писем сохраняются,
  запись остаётся в списке.
- Обратная галочка подключает запись сразу, перезапуск не нужен: видно
  окно хода подключения, затем ветка папок возвращается в дерево.
- Совсем убрать запись (вместе с её настройками) — правой кнопкой по
  верхней ветке ящика в дереве папок, «Отключить ящик».

В окне записи («Настроить…») есть группа **«Архив и переезд»**:

- **Удалять письма с сервера после переноса в архив.** По умолчанию
  выключено. Включённая галочка действует только для этой записи: на время
  переезда можно чистить старый ящик Exchange, не трогая новый в VK. Перед
  первым удалением программа один раз спрашивает подтверждение.
- **Замена домена получателей.** По одному правилу в строке, например
  `amurgpz.ru = vk.corp.amurgpz.ru`. Действует только для писем,
  отправленных с этой записи. В адресной книге и в письмах адреса остаются
  прежними.

Если до обновления правила замены или галочка удаления были заданы общими,
они сначала действуют для каждой записи. Откройте «Настроить…» у записей,
которым они не нужны, и уберите лишнее.

Письмо уходит из той учётной записи, в которой его начали, даже если, пока
вы писали, открыли папку другой записи.

Так удобно на время перехода с одной системы на другую: обе записи
заведены, работает та, у которой стоит галочка, а данные второй никуда не
деваются.

**Работа с письмами.**

- «Ответить», «Ответить всем», «Переслать» и «Открыть в окне» — строкой
  кнопок над реквизитами открытого письма (тема, отправитель, получатели).
- Del в списке писем переносит отмеченные или выделенные письма в корзину.
  Ctrl+Del удаляет безвозвратно, после подтверждения. В строке фильтра Del
  по-прежнему стирает текст.
- Удаление и перенос относятся к тому ящику, где их начали, даже если
  сразу щёлкнуть папку другой учётной записи.
- Сортировка, фильтры (важные, с вложениями, маркер, категория, колонка
  поиска) и группировка по теме у каждой учётной записи и архива свои:
  при переходе к папке другой записи возвращаются её настройки. Они
  сохраняются между запусками, текст в строке фильтра — только до
  закрытия программы.
- Цепочка писем в области просмотра и список цепочки над письмом идут от
  нового к старому, как и сам список писем.
- Приветствие первой строкой: Параметры → «Общие» → «Приветствие в начале
  письма». Варианты: не добавлять, «Здравствуйте!», по времени суток
  («Доброе утро!» до 12:00, «Добрый день!» до 18:00, «Добрый вечер!» до
  полуночи, ночью «Здравствуйте!»). Ставится в новом письме, ответе и
  пересылке; если текст уже начинается с приветствия, второе не добавляется.
- Даты писем Exchange показываются в местном времени, как у остальных
  ящиков. Письма, загруженные прежними версиями, переводятся один раз при
  подключении.

**Категории писем (модуль).** Параметры → вкладка «Модули» → группа
«Категории писем», галочка «Включён». Модуль включается и выключается без
перезапуска. Когда он включён, у
писем появляется колонка «Категория», в плитках — цветная метка, в меню
«Фильтр» — подменю «Категория».

Стандартные категории: «Уведомления и рассылки», «Обращения и запросы»,
«Реклама». Свои добавляются кнопкой «Категории…» → «Добавить…». У каждой
категории есть название, цвет, описание и правила:

- **Адресаты**, по одному в строке: домен (`nalog.ru`), адрес или маска
  со звёздочкой (`*@gosuslugi.ru`, `noreply@*`) или часть имени
  отправителя (`Иванов`).
- **Слова в теме** письма.

Как письмо получает категорию, по порядку:

1. Выбранная вами вручную (правой кнопкой по письму → «Категория»). Она
   не меняется автоматически.
2. По адресатам из описания категории.
3. По признакам рассылки в самом письме (ссылка отписки, массовая
   отправка, автоответ); рассылка с рекламными словами — «Реклама».
4. По словам темы из описания категории.
5. По обучению. Каждый ручной выбор учит модуль. Когда в категории
   наберётся хотя бы пять размеченных вами писем, похожие письма получают
   её сами, если модуль достаточно уверен. Во всплывающей подсказке у
   категории видно, как она определена.

Всё хранится только на этом компьютере, в файле `categories.sqlite3` в
каталоге профиля, и на сервер не уходит. «Разметить письма заново» в окне
категорий сбрасывает автоматическую разметку после правки правил; выбранное
вручную сохраняется.

## 4. Exchange (EWS)

Параметры → вкладка «Учётные записи» → «Подключить Exchange (EWS)».

- Автопоиск настроек (autodiscover) в закрытом контуре часто не работает.
  Тогда адрес сервера указывается вручную. Достаточно имени узла
  (`svb-mail.corp.amurgpz.ru`); ссылку целиком
  (`https://<сервер>/EWS/Exchange.asmx`) тоже можно вставить — программа
  возьмёт из неё имя узла.
- Синхронизируются только почтовые папки. Задачи, заметки, контакты,
  журнал, папки Yammer, SearchLog и прочие служебные пропускаются: почты
  в них нет, а лишние запросы сервер ограничивает.
- Цвет маркера письма Exchange отдаёт только вместе с письмом целиком,
  поэтому цвета, проставленные в Outlook, в список не переносятся.
  Проставленные здесь — на сервер уходят.
- Письма, удалённые в Outlook или на телефоне, пропадают и здесь при
  следующем обходе папки. Если такое письмо успели открыть или удалить до
  обхода, программа просто убирает его из списка без ошибки.
- Колонка «Кому» в «Отправленных» заполняется, в том числе у писем,
  загруженных прежними версиями: получатели дописываются при первом обходе.
- Если адрес открывается в браузере, а программа сообщает
  `CERTIFICATE_VERIFY_FAILED`, дело в сертификате: см. раздел 6.

## 5. Календарь: Exchange, CalDAV и подписка

Календарей может быть несколько, у каждого свой источник. Создание:
Календарь → «Календари» → «Новый календарь…», поле «Источник».

| Источник | Когда выбирать | Что нужно указать | Направление |
|---|---|---|---|
| Локальный | встречи только на этой машине | ничего | — |
| Exchange (EWS) | почта организации в Exchange, календарь отдаётся тем же протоколом | ничего: берётся подключённая учётная запись Exchange | чтение и запись |
| CalDAV | сервер поддерживает CalDAV (VK Mail и др.) | адрес сервера, кнопка «Найти календари на сервере…» | чтение и запись |
| Подписка (.ics) | Google Календарь и любой опубликованный календарь | закрытый адрес в формате iCal | только чтение |

**Exchange (EWS).** Отдельный адрес и пароль не нужны: календарь берётся
из той же учётной записи Exchange, что и почта (раздел 4). Порядок:

1. Подключить учётную запись Exchange: Параметры → «Учётные записи» →
   «Подключить Exchange (EWS)». Календарь с именем «Exchange: <адрес>»
   создаётся при этом сам, отдельно добавлять его не нужно.
2. Если календаря почему-то нет (учётная запись подключена давно):
   Календарь → «Новый календарь…», источник «Exchange (EWS)», название на
   ваш вкус.
3. Синхронизация идёт сама: примерно через 20 секунд после подключения
   почты, затем каждые три опроса почты, а также сразу после того, как вы
   сохранили, перенесли или удалили встречу. Вручную — кнопка
   «Синхронизировать» на панели календаря.
4. Приглашения, изменения и отмены участникам встреч в календаре Exchange
   рассылает сам Exchange. Отдельное письмо с приглашением программа для
   таких встреч не отправляет, чтобы у участников не было дублей.

Читаются тема, время, место, описание, организатор и участники с их
ответами (принял, отклонил, под вопросом). Отменённые встречи помечаются
как отменённые.

**CalDAV.** Календарь → «Новый календарь…», источник «CalDAV», адрес
сервера. Кнопка «Найти календари на сервере…» показывает доступные
календари и подставляет адрес выбранного.

Логин и пароль календаря берутся от той учётной записи почты, чей сервер
ближе всего по адресу: для `calendar.vkm.corp.amurgpz.ru` это почта
`imap.vkm.corp.amurgpz.ru` с паролем приложения. Подходит и запись,
выключенная галочкой. Какая папка открыта в почте, значения не имеет.

**Как идёт синхронизация.** Для каждого календаря по очереди:

1. Встречи, удалённые здесь, удаляются на сервере.
2. На сервер уходят только встречи, изменённые здесь с прошлой
   синхронизации. Если сервер отвечает, что встречу уже меняли в другом
   месте (для VK это ответ 412), верной считается серверная копия.
3. С сервера забираются встречи с 30 дней назад до полугода вперёд.
   Встречи, которых на сервере больше нет, убираются и здесь.

Ошибка одной встречи или одного календаря не останавливает остальные.
Итог виден в строке состояния, подробности пишутся в журнал.

**Подписка (ICS).** Источник «Google Календарь / подписка по ссылке»,
адрес вида `https://calendar.google.com/calendar/ical/…/basic.ics`.
Обновляется при синхронизации, правки на сервер не уходят.

**Встречи из писем.** Приглашения, изменения, отмены и ответы участников
попадают в календарь из писем сами, в том числе из писем, которые не
открывали: их разбирает фоновая загрузка почты. Учитывается и обычный
файл встречи во вложении (`meeting.ics`). Правила:

- Отмену и изменение уже известной встречи принимаем только от её
  организатора, ответ участника — только от самого участника. Иначе при
  открытии письма видно, что изменение не внесено и от кого оно пришло.
- Файл `.ics` без приглашения добавляет новые встречи, но не
  перезаписывает уже известные.
- Встречи, закончившиеся больше 30 дней назад, из писем не добавляются.

Ошибка «Не удалось получить список календарей» с текстом про сертификат
разбирается в разделе 6.

## 6. Сертификаты организации (важно для календаря и Exchange)

Почта и браузер берут доверенные корни из разных мест:

| Программа | Где берёт доверенные корни |
|---|---|
| Браузер на RED OS | системное хранилище через p11-kit и собственная база NSS в профиле пользователя |
| Почта, IMAP и SMTP | системное хранилище (OpenSSL) |
| Почта, HTTPS: CalDAV, Exchange, подписка | набор из настроек программы, иначе системное хранилище |

Поэтому адрес, который открывается в браузере, может не открыться в
программе: корпоративный корневой сертификат стоит в браузере, но не в
системном хранилище.

**Шаг 1. Проверить системное хранилище:**

```bash
openssl s_client -connect svb-mail.corp.amurgpz.ru:443 -CAfile /etc/pki/tls/certs/ca-bundle.crt </dev/null 2>&1 | grep "Verify return code"
```

`Verify return code: 0 (ok)` — корень в системе, программа подключится
сама. Ответ про `unable to get local issuer certificate` — корня в системе
нет, дальше шаг 2.

**Шаг 2. Получить файл с корнем.** Из цепочки сервера:

```bash
openssl s_client -showcerts -connect svb-mail.corp.amurgpz.ru:443 </dev/null 2>/dev/null | awk '/BEGIN CERT/,/END CERT/' > ~/corp-chain.pem
```

Если сервер не отдаёт сам корневой сертификат, выгрузите его из браузера
(свойства сертификата, экспорт в PEM) или возьмите у администратора.
Посмотреть, что есть в базе браузера:

```bash
certutil -L -d sql:$HOME/.pki/nssdb
```

**Шаг 3. Указать корень.** Любой из двух способов:

- Для всей системы (рекомендуется, действует и на другие программы):

  ```bash
  sudo cp ~/corp-chain.pem /etc/pki/ca-trust/source/anchors/corp-root.crt
  sudo update-ca-trust
  ```

- Только для почты: Параметры → вкладка «Общие» → «Корневой сертификат
  (PEM)», указать файл. Пустое поле означает системное хранилище.

После изменения программу нужно перезапустить. В журнале появится строка
`HTTPS: доверенные корни из ...` с выбранным набором.

## 7. Хранилище и обслуживание

Параметры → вкладка «Хранилище».

- **Каталог профиля**: по умолчанию `~/.config/redmail/profile`. Там лежат
  почтовая база `mail.sqlite3`, календарь, контакты и каталог `archives`.
  Смена каталога вступает в силу после перезапуска.
- **Не скачивать фоном письма больше**: письма крупнее порога скачиваются
  по требованию, при открытии.
- **Автоархив по размеру базы**: когда база превышает порог (по умолчанию
  500 МБ), самые старые письма переносятся в файлы архива, база
  сжимается. Архивы открываются из дерева папок как обычные папки.
- **Часы обслуживания**: если включены, автоархив, докачка писем и сжатие
  базы выполняются только в указанный промежуток, например с 22:00 до
  7:00.

Синхронизация: список текущей папки и «Входящие» проверяются по таймеру
(по умолчанию каждые 5 минут), полный проход по всем папкам — раз в
полчаса и только если предыдущий закончился. Папка назначения
досинхронизируется сразу после переноса писем: корзина после удаления,
«Отправленные» после отправки, «Черновики» после сохранения черновика.

## 8. Голосовой помощник

Помощник — подключаемый модуль. Управление из почты: Параметры → вкладка
«Модули» → группа «Голосовой помощник».

- Состояние, версия, ключевое слово (по умолчанию «Вика»).
- Галочка «Включён» запускает службу пользователя `audioreferent.service`
  и включает автозапуск.
- Кнопки «Настройки помощника…», «Журнал помощника…», «Проверить связь».

Голоса синтеза: irina (по умолчанию), denis, dmitri. Распознавание —
Vosk, офлайн. Команды: «открой почту», «создай встречу», «перенеси
встречу», «отмени встречу», заполнение формы встречи голосом, выбор
участников через адресную книгу («участники Шилкин», затем «второй»,
«принять»).

**Встреча разговором.** После «Вика, создай встречу» помощник сам
спрашивает по очереди то, что не названо в команде: тему, день, время,
длительность, календарь (если их больше одного), участников и место.
Поле, о котором спрашивают, подсвечивается в окне встречи.

- Отвечайте просто значением: «планёрка отдела», «завтра», «в десять
  тридцать», «час», «эксчейндж», «Шилкин», «кабинет сто двадцать».
  Ответ можно повторить, чтобы исправить.
- «Дальше» — следующий вопрос, «назад» — предыдущий. Участников можно
  называть несколькими фразами, затем «дальше».
- В конце «Сохранить встречу?»: «да» сохраняет, «нет» оставляет окно
  открытым для правки.
- Слова-поля работают как раньше, в любой момент: «место …», «описание …».

**Выбор календаря.** «Календарь эксчейндж», «календарь вк», «календарь мои
встречи» или по номеру: «календарь два». Нумерация — как в списке «Мои
календари». Если календарь не нашёлся, помощник перечисляет, какие есть.
Без выбора встреча создаётся в календаре, выделенном в списке «Мои
календари», а если ничего не выделено — в «Мои встречи».

Для разговорного режима и выбора календаря нужны почта 0.0.1-117 и
помощник 0.1.0-9. Вопросы произносит синтез речи, поэтому в настройках
помощника должен быть включён голосовой ответ.

Служебные команды в терминале:

```bash
systemctl --user status audioreferent.service
journalctl --user -u audioreferent.service -n 50 -o cat
```

## 9. Журналы и диагностика

Журнал почты: `~/.config/redmail/logs/redmail.log` (плюс `.1`, `.2` —
предыдущие). Открыть из программы: Справка → «Журнал подключений».

Полезные проверки:

```bash
grep ERROR ~/.config/redmail/logs/redmail.log | tail -20
grep "redmail.app: Версия" ~/.config/redmail/logs/redmail.log | tail -1
grep "HTTPS: доверенные" ~/.config/redmail/logs/redmail.log | tail -1
```

Если окно перестало отвечать, снимок стека покажет, где именно:

```bash
/opt/redmail/venv/bin/py-spy dump --pid $(pgrep -f 'venv/bin/python3 /usr/bin/redmail' | head -1)
```

## 10. Типовые сообщения и что они значат

| Сообщение | Причина и что делать |
|---|---|
| `NEOBHODIM parol prilozheniya` | сервер требует пароль приложения, создать его в веб-интерфейсе почты |
| `CERTIFICATE_VERIFY_FAILED` | неизвестный корневой сертификат, см. раздел 6 |
| `[SERVERBUG] Internal error` | внутренний сбой почтового сервера на команде; программа переподключается и повторяет запрос сама, при повторах — вопрос к администратору сервера |
| `All steps in the autodiscover protocol failed` | автопоиск Exchange не прошёл, указать адрес EWS вручную |
| `GSSAPI ... обмен прерывается протокольной ошибкой` | вход по Kerberos не поддерживается сервером фактически, войти по логину и паролю |

## 11. Обновление

Обновление ставится поверх, настройки и профиль сохраняются:

```bash
sudo dnf install ./redmail-0.0.1-<новая сборка>.red80.x86_64.rpm
```

Если база почты большая и давно не сжималась, при первом запуске новой
сборки программа может один раз сжать её под заставкой. Это нормально и
занимает до нескольких минут.

## 12. Фирменное оформление организации

Программа нейтральна: цвета, шрифты, вид письма и стандартную подпись задаёт
заказчик — у каждой дочерней организации свой файл оформления JSON. Пример с
описанием полей: `docs/brands/пример-организации.json`.

Где лежат оформления:

- `/etc/redmail/brands/*.json` — раскладывает администратор, действуют для
  всех пользователей машины и в программе не меняются;
- `~/.config/redmail/brands/*.json` — оформления, созданные пользователем в
  «Параметры» → «Общие» → «Оформления организаций…». Системное оформление с
  тем же кодом пользовательским не подменяется.

Что входит в оформление:

| Раздел | Что задаёт |
|---|---|
| `colors` | цвета программы поверх светлой или тёмной основы (`base`) |
| `font` | шрифт и размер программы; шрифт должен быть установлен, иначе остаётся системный (запись в журнале) |
| `letter` | шрифт, размер и цвет текста нового письма и ответа; `footer_html` — колонтитул, добавляется в конец письма только при отправке |
| `signature_html` | шаблон стандартной подписи; `{name}`, `{title}`, `{department}`, `{organization}`, `{phone}`, `{email}` берутся из карточки сотрудника в адресной книге (по адресу учётной записи); строка с пустой подстановкой в подпись не попадает |
| `default` | `true` — оформление по умолчанию для тех, кто тему ещё не выбирал |

Как разложить оформление по машинам: создать и проверить его в окне
«Оформления организаций…», нажать «Выгрузить файл…» и скопировать файл:

```bash
sudo install -D -m 0644 gpp.json /etc/redmail/brands/gpp.json
```

Выбор оформления — в списке «Тема оформления» («Оформление: <название>»).
Фирменная подпись появляется в списке подписей как «Фирменная: <название>»,
обновляется перед каждым новым письмом и становится подписью по умолчанию,
если своей у сотрудника нет.

## 13. Перенос профиля и выгрузка переписки

«Параметры» → «Хранилище» → «Перенос на другой компьютер и выгрузка переписки».

- **Выгрузить профиль…** — один файл `.rmprofile`: настройки и учётные
  записи, почта, календарь, контакты, категории, архивы и свои оформления.
  Пароли не переносятся (они в хранилище ключей компьютера) — на новом
  компьютере их вводят заново. Файл не зашифрован: храните и передавайте его
  как саму переписку.
- **Загрузить профиль…** — проверяет файл и загружает его при следующем
  запуске программы. Прежние данные не удаляются: они переезжают в
  `~/.config/redmail/backup-before-import-<дата>`. Ошибка в файле (не сошлась
  контрольная сумма, посторонние файлы) — загрузка не выполняется, данные
  остаются прежними.
- **Выгрузить переписку…** — вся переписка и архивы в новый каталог:
  **mbox** (файл на папку; Thunderbird, Evolution) или **EML** (файл на
  письмо; открывается Outlook и любой почтовой программой). Письма, тело
  которых ещё не скачано с сервера, выгружаются только с реквизитами — их
  число показывается в итоге.

Кто это делает, решает организация:

| Оформления в `/etc/redmail/brands` | Поле `data_export` | Кто выгружает |
|---|---|---|
| нет | — | сам пользователь |
| есть | `"user"` или не указано | сам сотрудник, запись в системный журнал |
| есть (хотя бы в одном) | `"admin"` | только администратор; кнопки в программе недоступны |

Администратор выполняет те же действия из командной строки от root; `--home` —
домашний каталог сотрудника (программа сотрудника при загрузке профиля должна
быть закрыта):

```bash
sudo redmail --export-mail /srv/выгрузки/ivanov --format mbox --home /home/ivanov
```

```bash
sudo redmail --export-profile /srv/выгрузки/ivanov.rmprofile --home /home/ivanov
```

```bash
sudo redmail --import-profile /srv/выгрузки/ivanov.rmprofile --home /home/ivanov
```

Каждая выгрузка и загрузка записывается в журнал программы и в системный
журнал (`journalctl -t redmail`): что, куда, сколько писем и кто выполнил.
Режим «только администратор» — организационное правило, а не защита от
копирования: файлы профиля принадлежат пользователю.
